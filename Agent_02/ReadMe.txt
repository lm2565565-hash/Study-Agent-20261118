Agent
langchain  调用工具 手搓
create_agent()  #自动化绑定工具

特点：自主做决策
路径规划能力：自主调用工具、mcp服务、skill

Agent前置条件：
大模型（负责思考和决策）
工具集合（提供可执行的能力）
用户任务（告诉智能体要完成什么）
执行机制（负责调用工具并把结果反馈给模型）

agent是大模型根据任务和执行结果决定下一步做什么

为什么能调用工具？核心 Function Calling
大模型只是能够按照约定的格式，生成工具调用的请求

#工具
def query_stock(sku:str):
  return {"sku":sku,"stock":20}
pass

让大模型知道这个工具【工具说明书】
用户：查询 sku001 的库存
大模型不会直接回答，会生成一个结构化的工具调用请求
{
  "name":"query_stock",
  "arguments":{
  "sku":sku001
  }
}
接下来由agent运行框架负责真正执行python函数

llm               判断调用哪个工具 生成参数
agent runtime     接收工具请求、查找并执行工具
tool              执行实际业务逻辑并返回结果

技能、mcp 都是相同的道理

后续
多工具---mcp----skill----进阶可交付工程能力----agent 智能体框架

agent 重要性：根据用户目标和执行的结果  动态的决定下一步的行动
帮我分析一下订单管理系统为什么延期了，请给出解决的建议
agent 如何做？
1. 查询订单管理系统的基本信息
2. 获取所有的订单任务
3. 筛选未完成或者已经延期的任务
4. 分析延期原因
5. 生成风险分析报告和解决建议

结构化的数据： 让大模型按照预先定义的数据结构返回结果，而不是随意组织自然语言

结果：
 单个商品信息 【商品编号、商品名称、采购数量、预计贡献毛利率】

 选品结果
   是否成功
   推荐商品列表
   总采购投入
   总预算
   是否通过初步审核

 分析报告
  推荐理由
  市场分析
  风险提示
  最终结论

selectionResult
   success:是否成功
   selected_products:推荐商品列表
   total_inverstment:采购总投入
   budget:预算
   report_summary:报告

测试场景

正常的场景    预算10000， 推荐2款商品  毛利率不低于30%   正常完成选品
边界场景      预算5000，  推荐2款商品  毛利率不低于45%   只推荐满足条件的商品   [3] 毛利率只有一个商品符合
不可行的场景   预算5000，  推荐2款商品  毛利率不低于70%   返回失败  不在重复计算
